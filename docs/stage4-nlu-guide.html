为什么没有现成数据集可用

公开的中文意图识别数据集解决不了这个项目的问题，原因有三：

  1. 域太窄：只有 8 个意图，全围绕「灯 / 蜂鸣器」两块硬件。公开数据集的意图（订票、查天气……）一个都用不上；而这个窄域的口语表达，没有人替你整理过。
  2. 输入形态特殊：串口 / 网页输入的是一句「命令」，夹杂「帮我」「麻烦」这类礼貌语和口语省略，与通用语料里书面句子的分布差很远。
  3. 模型太小：目标是 <100 KB 的端侧模型，没有能力「泛化理解」——只能用贴合真实使用的样本，教它认识这个窄域里的固定模式。

所以数据必须自己造。而「怎么造」决定了模型能学到什么、也决定了测试成绩可不可信——这就是下一章的六个关键决策。

train / val / test 各自做什么

数据集会切成三份，用途严格区分。这条纪律不守，评估结果就会骗你：

集合比例用途纪律
训练集 train80%模型学习参数反复使用
验证集 val10%调超参、监控过拟合、决定何时停训练期间可反复看
测试集 test10%最终成绩单训练中绝不碰，只考一次

为什么 test 只能考一次：每调一次参数就用 test 测一次，等于拿 test 当 val 用——测到满意为止，就是对考题改答案，成绩不再反映真实水平。调参看 val，宣布最终成绩时才动 test。

六个关键决策

这一章回答「为什么这么做」。六个决策合起来，就是这套语料方案的全部方法论——后面的实操只是它们的执行。

决策一：字符级，而不是分词

中文 NLP 的第一道选择题是：把句子切成什么单位喂给模型？

  • 分词级：先用分词器切成词——「帮我 / 开 / 灯」，每个词一个 token。
  • 字符级：每个汉字或字母就是一个 token——「帮 / 我 / 开 / 灯」。
维度分词级字符级（本项目）
词表大小数千～数万词几百个字符（预计 <500）
分词器需要词典 + 分词算法不需要：逐字符查表
未登录（OOV）风险口语变体常未收录，如「开下灯」只剩生僻字一种情况
C 侧实现量高（要把分词器带上板）低（UTF-8 解码 + 查表，约 20 行）
序列长度短（一句约 8 个词）长（一句约 15 个字）
单 token 信息量高（一个词一个义）低，靠「多个字一起看」的卷积窗口补回

选字符级的根本原因是端侧约束：分词器要配词典、算法和几百 KB 级资源，而应用分区只有 1.9 MB；口语变体又最容易踩未登录词的坑。字符级的代价是序列变长、单个字符信息量小——这正好由 TextCNN 的多尺度卷积窗口（k=2/3/4）来补：「开」「灯」两个字符相邻出现，k=2 的窗口就能把「开灯」这个模式抓出来。

决策二：模板 × 槽位——受控的数据增强

造语料有三条路：收集真实语料（这个域没有现成来源）、人工一句句写（覆盖不全、难统计）、程序化生成。本项目选第三条——句式模板 × 同义词槽位：

模板 {polite}{act_on}个{dev_light} → 展开（5 × 4 × 4 = 80 句）
帮我开个灯请点个台灯麻烦打开个小灯给我开个LED帮忙开启个台灯麻烦点个小灯…

这在方法论上就是数据增强（同一语义的多种说法变体），只是「受控」的：每个变体可追溯来源模板、可统计、固定种子可复现，不会有真实语料里的脏数据问题。它的局限也要认清——句式多样性上限 = 写模板时能想到的说法，所以阶段 8 要用真实输入持续迭代补充。

决策三：先划模板，再落句子（防泄漏）

切分 train / val / test 时，不能简单地把生成的句子随机分堆。看一个例子：

随机划分（错的）

train：帮我开灯、帮我开台灯、请开灯 …
test：帮我开LED

test 这句和 train 只差一个槽位词，模型背下「帮我开X」模式后几乎必然答对——考的是记忆，不是泛化，准确率虚高。

模板级划分（对的）

train：模板「帮我开X」的全部 80 句
test：「把X打开」等其他模板家族

整个模板家族的句子只进一个集合，test 里的句式训练时从未见过——考的是「换个说法还认不认得」，正是阶段 6「手敲现编口语」的场景。

做法：先给每个类别的模板按 8:1:1 分堆（比如 50 个模板 → 40/5/5），再让该模板生成的所有句子跟随它所属的集合。这样 test 成绩才有资格代表「真实口语表现」。

决策四：unknown 不是「剩下的」，是一类

softmax 层有个数学事实：8 个输出概率之和恒为 1，取最大值永远有结果。也就是说，无论输入什么——哪怕「今天天气不错」——模型都必须给出一个意图。拒识不能指望模型「自己知道不知道」，要靠设计：

  • 方案 A：只训 7 个动作类，部署时靠「置信度过低 → 拒识」判断。简单，但模型从没见过「无关输入」长什么样，容易把无关句高置信度地误判成某个动作。
  • 方案 B（本项目）：把 unknown 当作正式的第 8 类训练——让模型直接从样本里学会「这不是一条命令」。

unknown 语料分三种成分，各有明确分工：

成分占比例子作用
完全无关≈40%今天天气不错 / 你叫什么名字教「闲聊不是命令」
域内无关（难例）≈35%把空调打开 / 把灯调成红色 / 灯会不会闪吗含设备词但无动作——与动作类字符重叠最大，最难分，必须占足比重
噪声≈25%单字、重复、乱敲、超长拼接覆盖真实场景里的乱输入

部署后（阶段 6）还会加第二道闸门：模型置信度低于阈值时，先让关键词规则兜底再试一次，都不中才回「没听懂」。所以拒识是两道闸门：训练出的 unknown 类 + 部署时的阈值判断。

决策五：词表——把字变成编号

模型不认识汉字，只认识数字。词表（vocab）就是「字符 ↔ 编号」的对照表：语料里出现过的每个不同字符占一行，行号就是它的 id。

vocab.txt 前几行（格式示意） 
<pad>     ← id 0：补位符，把短句垫到统一长度用
<unk>     ← id 1：未登录字符的占位符
开        ← id 2
灯        ← id 3
…（按频次降序，同频按 Unicode 码点升序）
  • <pad>：一句话只有 5 个字、模型要求输入 20 个 token，多出的 15 个位置用 pad 填充——它们不参与信息表达（靠池化层自然屏蔽）。
  • <unk>：推理时遇到词表外的字符（生僻字、Emoji）时的占位。训练语料按定义全在词表内，unk 只在部署期起作用。
  • 为什么上限 500：命令句的用字高度集中（预计全语料 400 个左右不同字符）。词表大小直接决定第一层 Embedding 的参数——500 × 32 维 ≈ 1.6 万参数，受控；若混入英文长句、生僻话题，几百字就膨胀起来了，所以 unknown 语料也控制用字。

决策六：规模与均衡——每类 500 条的来历

  • 量级匹配：模型总参数约 3.6 万（估算，第 3 章细算），语料约 4000 条——小模型不需要海量数据，需要的是「覆盖够多句式、且句式别重复」。
  • 类别均衡：生成器按配额精确采样，每个动作类都是 500 条。类别不均衡会让模型偏向样本多的类，小模型上尤其明显。
  • unknown 例外：600 条（+20%），因为拒识是端侧 NLU 最主要的失败点，多给样本合理。
  • 质量 > 数量：模板生成的是「受控重复」，堆到上万条边际收益趋零。真正让模型变强的，是模板数（句式多样性），不是同一模板的更多变体。

阶段 4：语料实操

决策讲完了，这一章把「怎么造」落到本项目的真实文件上：语料源长什么样、生成器做哪四步、产物怎么看。

语料源：一个 JSON 管全部

整份语料来自 tools/intents.json，就是三个部分：

{
  "slots": {          ← 槽位：一个名字 → 一组合法替换词
    "dev_light": ["灯", "LED", "台灯", "小灯"],
    "polite":    ["帮我", "请", "麻烦", "给我", "帮忙"],
    …
  },
  "intents": {        ← 每个意图一串模板；{槽位名} 会被展开
    "led_on": [
      "{polite}{act_on}{dev_light}",
      "把{dev_light}{act_on2}",
      "把灯点上",     ← 不含花括号＝固定句，原样收录
      …
    ],
    …
  },
  "noise": { "ratio": 0.25 }   ← unknown 噪声占比（脚本按规则生成）
}
  • 槽位是「同义词池」：改一处（如给 dev_light 加「吊灯」），所有引用它的模板一起扩充。
  • 固定句（不含 {} 的元素）负责模板组合写不出的口语表达，如「把灯给我打开」「来点光」。
  • 整个文件共 8 个意图、约 400 条模板元素——这就是人工创作的全部工作量，之后机器负责放大。

生成器做四步

  1. 展开：把每个模板的 {槽位} 替换成全部组合并去重。例：{act_on}{dev_light} → 4 × 4 = 16 句（开灯 / 打开灯 / 点LED …）。
  2. 采样（按模板均分）：目标 500 条 ÷ 模板数，每个模板分摊固定配额，各自随机取——这样写了 200 种组合的模板也不会霸榜（它也只取自己的 10 条），句式的多样性由「模板」这个单位保证。
  3. 划分：先给模板按 8:1:1 分堆，模板生成的句子跟随所在堆进入 train / val / test。
  4. 自检：模板泄漏（同模板跨集合即报错）、单句长度、字符集规模、每类模板数下限，任一不过就报错退出。

固定种子（seed = 42）：采样和划分的随机数都从固定种子出发——同一份语料源任何时候重跑，产物逐字节一致。这是「源入库、产物不入库」方案成立的前提：产物永远可以从源一条命令复现。

文件内容谁消费

怎么判断「语料合格」

对照阶段 4 验收清单，逐项过：

  • 可复现：同种子跑两遍，TSV 逐字节一致。
  • 条数均衡：报告里 8 个类条数齐平（动作类各 500 左右，unknown 600）。
  • 词表受控：全语料字符集 ≤ 500；阶段 1 的验收句（「开灯」「闪」「报警」「停止」…）全部落在词表内。
  • 无泄漏：模板级划分自检通过。
  • 人工抽查：从 test.tsv 随机抽几十句通读——检查有没有病句、标注错位；再从抽出的句子挑 30 句打进板子，看关键词规则在真实链路上的表现（这一步同时为「规则兜底基线」采样）。

阶段 5：模型训练

这一步把 4000 条文本变成约 3.6 万个浮点数——模型。先看清数据长什么样，再解剖网络，最后讲训练与评估。

第一步：文字 → 数字序列

每条语料先经过和部署时完全相同的预处理——训练用什么编码，上板就用什么编码，两边不一致是端侧部署最常见的坑：

原文把灯打开
逐字符查 vocab.txt458712112
padding 到统一长度（max_len＝8，示意） 458712112 0000

上面编号均为示意，实际编号以生成的 vocab.txt 为准。max_len 取语料长度的 P99.9（报告里给出，预期 ≤20），所有句子垫到等长才能组成批次的张量。这一步的产物是形状 (样本数, max_len) 的整数矩阵。

网络解剖：字符级 TextCNN

  • Embedding（词表 × 32）：把字符 id 换成 32 维浮点向量。这些向量不是预设的，是训练学出来的——意思相近的字（如「开」「启」）会逐渐靠近。（实现上用裸 tf.gather 查表层，原因见量化一节的实战细节。）
  • 并联 Conv1D（k=2/3/4，各 64 通道）：卷积核在序列上滑动。k=2 看两个字（「开灯」）、k=3 看三个字（「打开灯」）、k=4 看四个字（「把灯打开」）——不同长度的关键词模式由不同路同时抓取。
  • GlobalMaxPooling：每路输出取全局最大值，等价于问「这句话里最强的那个 n-gram 特征有多强」。代价是位置不敏感：「灯开」和「开灯」池化后可能很像——口语语序灵活，这反而是优点；但「别开灯」这类靠语序/否定表达含义的句子就难学（已知局限，阶段 8 再补）。
  • Concatenate → Dense(8) → softmax：三路池化结果拼成 192 维，经全连接层投到 8 个类别，softmax 归一化成概率。

参数量估算（也是「<100 KB」的依据）：

层参数计算数量
Embedding 500 × 32500 × 3216,000
Conv1D k=2, 64 通道2 × 32 × 64 + 644,160
Conv1D k=3, 64 通道3 × 32 × 64 + 646,208
Conv1D k=4, 64 通道4 × 32 × 64 + 648,256
Dense 192 → 8192 × 8 + 81,544
合计（估算）≈ 36,000

float32 时约 145 KB，int8 量化后约 36 KB（第 4 章展开）——余量足够的 <100 KB。

训练循环：让参数自己找方向

训练做的事很朴素：把 train 集一遍遍喂给模型，每遍算出「错得多远」（loss），反向传播把每个参数往让 loss 变小的方向挪一点。几个关键设定：

设定值作用
batch_size32一次喂 32 条，算一次平均梯度、更新一次参数
epochs + 早停最多 100 遍，val_loss 连续 5 遍不降即停防止越练越「死记硬背」；停时回滚到 val 最好的一版权重
优化器 / 损失Adam（默认学习率）/ 交叉熵交叉熵衡量「预测概率分布」与「正确类」的差距，分类任务标配
随机种子全部固定（Python / NumPy / TF）保证实验可复现，否则两次训练结果对不上
# 结构示意（Keras Functional API，实施时按所用版本微调）
inp = keras.Input(shape=(MAX_LEN,))
emb = keras.layers.Embedding(VOCAB, 32)(inp)

convs = [keras.layers.GlobalMaxPooling1D()(
             keras.layers.Conv1D(64, k, activation="relu")(emb))
         for k in (2, 3, 4)]                     # 三路并行

x   = keras.layers.Concatenate()(convs)          # 192 维
out = keras.layers.Dense(8, activation="softmax")(x)
model = keras.Model(inp, out)

model.compile(optimizer="adam",
              loss="sparse_categorical_crossentropy",
              metrics=["accuracy"])

stop = keras.callbacks.EarlyStopping(
    monitor="val_loss", patience=5, restore_best_weights=True)

model.fit(x_train, y_train,
          validation_data=(x_val, y_val),
          epochs=100, batch_size=32, callbacks=[stop])

评估：三个必须看的指标

  1. 测试集准确率（分类别看）：总体目标 ≥95%，但必须逐类看——unknown 或 stop 这类小类被平均分掩盖是常见问题。
  2. 混淆矩阵：行是真实类别、列是预测类别，对角线是答对数。它的价值在非对角线上——「谁被认成了谁」直接指向问题。读法示意：
真实 \ 预测led_offled_blinkstop
led_off98%1%1%
led_blink4%94%2%
stop3%1%96%

（数值为读法示意，真实矩阵是 8×8）上表说明：「关灯」的说法偶尔被当成「闪烁」——回到语料看这两个类的模板是不是有重叠句式，比调网络结构更有效。

  1. 拒识两个方向都要看：漏拒（无关句被当成命令执行——最糟，灯会莫名亮起来）与误拒（正常命令被判 unknown——体验差）。前者用 unknown 测试集样本量衡量，后者用动作类被判 unknown 的比例衡量。

评估纪律回顾：训练期间反复看 val、调超参；宣布成绩时才跑一次 test，把数字写进评估报告（阶段 5 的交付物之一）。

症状多半原因对策

阶段 5 后半：int8 量化

训练产出 float32 模型（约 145 KB）。上板前把它压成 int8（约 36 KB）——这一章讲清楚：压缩为什么可行、误差从哪来、怎么做前后对比。

为什么要量化

维度float32int8效果
每个参数占4 字节1 字节模型体积 ≈ 1/4（145 KB → 36 KB）
推理中间结果（激活）4 字节1 字节RAM 峰值明显下降
乘加运算浮点定点整数ESP32-S3 对 int8 有加速内核，通常更快
代价——有精度损失，要用评估确认「掉点可接受」

一个公式看懂量化

量化的本质：用一把等距的整数格尺去量一段实数的区间。假设某层权重落在 [−3.2, 3.4]，把这段区间线性摊到 int8 的 256 个格子上：

  • scale：一个格子代表多少实数（本例 0.0259）。范围越窄、格子利用越充分，误差越小——这就是「校准」存在的意义。
  • zero_point：让实数 0 也落在某个格子上的偏移（本例 −4）。没有它，0 附近的值会系统性偏移。
  • 误差上限 ≈ 半个格：整数量化必然「四舍五入」，0.013 这个量级通常不影响分类结论——但要靠评估证实，不能想当然。

全整型量化流程

  1. 训练出 float 模型（上一章产物）。
  2. 准备代表数据集：从训练集抽几百条喂给转换器，让它逐层统计输入的数值范围，定出每层的 scale / zero_point。用训练集，不用 test（test 只留给最终评估）。
  3. 转换：TFLiteConverter 全整型量化——权重、激活 int8；输入输出不显式量化（TF 新版不接受 int32 输入类型；不设定时输入保持原生 int32、输出 float32）。
  4. 得到 model_int8.tflite。
  5. 前后对比：同一个 test 集上跑 float 与 int8 两版模型，准确率差值目标 ≤1–2 个百分点；数字写进评估报告。
# 转换骨架（示意，实施时按所用版本微调）
def rep_data():
    for x in x_train[:200]:                 # 代表数据：训练集抽 200 条
        yield [x[None, :].astype("float32")]

conv = tf.lite.TFLiteConverter.from_keras_model(model)
conv.optimizations = [tf.lite.Optimize.DEFAULT]
conv.representative_dataset = rep_data
conv.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
conv.inference_input_type  = tf.int8
conv.inference_output_type = tf.int8

tflite_model = conv.convert()
open("model_int8.tflite", "wb").write(tflite_model)

两个实战细节（本项目实测）：① 文本模型的输入是 token id（int32，超出 int8 范围），量化时不要强行指定输入输出类型——不设定时输入保持 int32、输出 float32、权重与激活照常 int8，实测零掉点；② Embedding 层不要用 Keras 自带的：它的负索引语义会引入 TFLM 不支持的算子（SELECT_V2 不支持 int32），改用裸 tf.gather 查表层即可。另：训练与部署的编码必须一致（同一个 vocab.txt、同一个 max_len）。

导出进固件

把 .tflite 的二进制转成 C 数组（如 xxd -i model_int8.tflite > model_data.cc 或专用脚本），编译进固件。数组声明为 const 时放在 flash 的只读段，不占 RAM。具体接入方式（直接编译进应用 or 放进分区）在阶段 6 决定。

阶段 6：板端衔接

训练与量化完成后的下一步是把模型接进固件。这里只给全景，细节留到阶段 6 实施时展开。

部署时的双层决策

模型不是唯一决策者。部署后的判定按这个顺序进行——这正是「决策四」里两道闸门的落地：

三个实施要点

  • C 侧 tokenizer（约 20 行）：UTF-8 逐字符解码 → 查 vocab 表得 id → 词表外字符跳过 → 补 pad 到 max_len。因为它极简，字符级方案在端侧的优势在这里兑现。
  • 阈值调优：在 test 集上扫一遍，找「漏拒 / 误拒」平衡点；再用串口手敲真实验证。阈值不是拍脑袋，是评估出来的。
  • 验收标尺：手敲 20 句现编口语（不照抄训练语料），通过率 ≥ 2/3，且用阶段 4 的规则基线数对比——证明「模型明显优于纯规则」。

最容易踩的三个坑（本页重点回顾）

  1. 分布不一致：测试集要模拟「现编口语」，所以用模板级划分；训练和部署的编码（词表、max_len）必须逐字节一致。
  2. 拒识只做一半：只训 unknown 类不够、只靠阈值也不够——两道闸门都要有（决策四 / 阶段 6）。
  3. 用 test 调参：成绩单只能出一次，调参永远看 val（全景地图的纪律）。
