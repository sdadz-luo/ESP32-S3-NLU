# 阶段 4 细化设计：数据工程

本文是《项目路线图》阶段 4 的实施依据：为端侧 NLU 模型准备语料（阶段 5
训练、阶段 6 上线）。本阶段定稿意图表、建立可复现的语料生成流水线、导出
字符词表与数据划分，交出统计报告；并以语料反哺固件侧规则兜底。范围与完成
标志见 ROADMAP 阶段 4 一节。

> 状态：已完成，2026-10-02 验收通过。语料 3994 条（8 类 474–500 + unknown
> 596；词表 369 行，上限 500；建议 max_len = 22；同种子逐字节可复现）；
> 规则精化 76.2% → 84.4%；真板抽查 25/30 = 83.3%——5 条不一致均为已知
> 取舍（不含「关 / 停」的说法落拒识、跨设备句被单设备分支截胡）。

## 目标与范围

- **意图表定稿**：8 类（7 个可执行意图 + unknown），对齐 `app_types.h` 的
  `intent_t` 枚举；ROADMAP 意图表已同步补记 `stop`（代码与阶段 1 行为
  规格中它是一等意图），语料按 8 类全量覆盖
- **语料流水线**：模板 × 槽位组合生成，固定种子可复现；模板级划分
  train / val / test = 8:1:1
- **词表与统计**：字符级词表（≤500 字）导出；条数 / 长度 / 字符集统计报告
- **规则精化**：以语料说法扩充 `nlu.c` 词池（本阶段唯一固件改动，10 条
  优先级逻辑不动）；建规则基线混淆报告（供阶段 6 对比「明显优于纯规则」）
- 不包含：模型训练与量化（阶段 5）、C 侧 tokenizer 与推理（阶段 6）、
  分词 / 词向量路线（技术路线已定字符级）；数据增强以「同义词替换」为
  手段，不引入其他 NLP 技巧

## 意图表定稿

| 意图 | 语义 | 语料说法族示例（节选） |
| --- | --- | --- |
| led_on | 灯常亮 | 开灯 / 点灯 / 把灯打开 / 帮我亮个灯 / LED 亮起来 |
| led_off | 灯常灭 | 关灯 / 熄灭 / 把灯关掉 / 别亮着了 / 关一下灯 |
| led_blink | 灯闪烁（5Hz） | 让灯闪 / 闪烁模式 / 灯闪起来 / 来回闪 |
| beep_breath | 蜂鸣器呼吸（0.5Hz） | 呼吸声 / 慢速提示 / 呼吸提示音 |
| beep_alarm | 蜂鸣器报警（2Hz） | 报警 / 快响 / 警报声 / 急促响 |
| beep_off | 蜂鸣器停止 | 关闭蜂鸣器 / 别响了 / 安静 / 静音 |
| stop | 全部停止 | 停止 / 全停 / 都停下 / 全都关掉 |
| unknown | 拒识（不动作） | 见「unknown 语料配方」 |

意图 ID 沿用 `intent_t` 枚举序（即 `INTENT_NAME` 数组序），语料标签取
`led_on` 等小写名——C 侧日志、语料标签、基线脚本三方一致。

### 标注规范（边界规则）

语料标注以 STAGE1_DESIGN「行为规格」为唯一依据；下列边界为定稿口径：

- **停止类三分**：停止词 + 蜂鸣器对象 → `beep_off`；停止词 + 灯对象 →
  `led_off`；无对象 / 全对象 → `stop`（沿用行为规格优先级 1~3）
- **单设备不串扰**：`led_*` 模板不出现蜂鸣器词，反之亦然；语义确实跨
  两者的句子（「把两个都停掉」）归 `stop`，不为语料发明新意图
- **否定式只收「停止进行中」**：`别闪了` / `别响了` 语义是停止，归对应
  `*_off`；否定未发生的动作（`别开灯` / `不用开灯`）不收——字符级小模型
  难学到「别 + 动词」的极性差异，误判成正向动作比拒识更糟，列入已知局限
- **疑问式不收**：`灯怎么关` / `能开灯吗` 类不作命令标注（真机执行动作尚可
  接受，但与拒识边界纠缠），留给阶段 8 以真实输入定夺
- **间接口语克制收录**：明确指向停止发声的（`安静` / `静音`）归 `beep_off`；
  指向不明的（`太吵了` / `声音小点`）不收，列入已知局限
- 语料不带标点与空格；数字用阿拉伯数字，字母保留大写（`LED` / `Hz`）

## 语料流水线

### 目录与产物

```text
tools/                       # 脚本与语料源（入库，随 gen_font.py 先例）
├── intents.json             # 语料源：意图表 / 模板 / 槽位 / unknown
├── gen_corpus.py            # 生成 + 划分 + 自检 + 报告（纯标准库）
└── rule_baseline.py         # 规则基线混淆报告（与 nlu.c 同步维护）
data/corpus/                 # 生成产物（不入库，gitignore 整目录）
├── train.tsv / val.tsv / test.tsv
├── vocab.txt
└── report.md
```

```text
tools/intents.json ──┬─ gen_corpus.py ──→ data/corpus/{train,val,test}.tsv
（seed 固定）        │                     + vocab.txt + report.md
                     └─ rule_baseline.py ─→ 规则混淆矩阵与准确率报告
```

产物不入库：由「语料源 + 固定种子」确定性复现（clone 后一条命令），与
字库先例一致，避免派生态入库；阶段 5 训练前重新生成即保证与源同步。
TSV 保持文本级（`text \t label`），字符到 id 的编码归阶段 5 训练脚本。

### 语料源结构（intents.json）

```json
{
  "version": 1,
  "meta": { "_note": "下划线键为说明，生成脚本忽略", "per_intent": 500 },
  "slots": {
    "dev_light": ["灯", "灯光", "LED", "台灯"],
    "act_on": ["开", "打开", "点亮", "开一下"],
    "polite_pre": ["", "帮我", "请", "麻烦", "给我"],
    "polite_suf": ["", "一下", "吧", "谢谢"]
  },
  "intents": {
    "led_on": [
      "{act_on}{dev_light}",
      "{polite_pre}{act_on}{dev_light}",
      "把{dev_light}{act_on}",
      "{polite_pre}把{dev_light}{act_on}{polite_suf}"
    ]
  },
  "unknown": ["{dev_light}是什么颜色", "你会做什么"],
  "noise": { "_note": "unknown 噪声补充（脚本按规则生成）", "ratio": 0.25 }
}
```

（含 `{槽位}` 的元素自动组合展开，纯固定句原样收录；unknown 与其余
意图同为模板数组，多出的 `noise` 为 unknown 专属的噪声生成配置。）

（示例仅示意结构与组合方式，完整词条在实施步骤 2 编写。）

### 生成算法

1. **展开**：逐意图枚举 模板 × 槽位全组合，组合结果去重（空槽位可能
   使两条模板产出同一句）
2. **采样（按模板均分）**：目标条数按模板数均分（余数随机给部分模板
   +1），每模板从自己的组合里以固定种子采样，避免高组合模板霸榜；组合
   数不足配额的模板全取，总缺口在报告中提示（需补模板）
3. **划分**：**先划模板、再落句子**——同一模板生成的句子只进同一集合
   （防模板泄漏；测试集因此由「没背过的句式」构成，贴近阶段 6 手敲现编
   的验收场景）；以 8:1:1 为目标、按各模板产出量贪心分配（模板产出是
   整数块，实际约 7.4 : 1.3 : 1.3，报告如实记录）。val 供阶段 5 调参 /
   早停，test 只在最终评估用一次
4. **自检**：模板泄漏（同模板跨集合即报错退出）、单句超长、每类模板数
   下限（< 20 告警）、空类、字符集超限
5. **输出**：三集 TSV（UTF-8，LF）+ `vocab.txt` + `report.md`（生成参数、
   各类条数表、长度分布、字符集与词表预览、自检结果、建议 max_len）

### unknown 语料配方

（约 600 条；占比为近似值）

- **完全无关（≈40%）**：天气 / 闲聊 / 常识（`今天天气不错`、`你叫什么名字`），
  用字限定常用字内，不上生僻话题
- **域内无关（≈35%）**：提到设备但非动作（`灯是什么颜色`、`蜂鸣器怎么用`、
  `把灯调成红色`）——与动作类字符重叠最大，是拒识难例，占比不可压
- **噪声（≈25%）**：单字 / 重复（`哈哈哈`）/ 乱敲（`asdf`）/ 超长拼接；
  由脚本按规则生成（固定种子），不写人工词条

### 数量目标

| 项 | 目标 | 说明 |
| --- | --- | --- |
| 每意图条数 | 500 | 生成器精确采样，各类均衡 |
| unknown | 600 | 拒识是主要失败点，允许多 20% |
| 模板数 / 意图 | 40~60 | 句式多样性的主要来源 |
| 单句长度 | ≤ 20 字 | `cmd_q` 128 B 余量充足；生成时校验 |

## 词表与长度

- **词表口径**：train + val + test 全部语料字符的并集（字符级，不归一大小
  写）——取全量并集而非仅 train，词表定位是「部署期覆盖集」而非学习参数，
  字符级小词表下可忽略的 test 字符泄漏换取推理期更好的覆盖
- **文件格式**：`vocab.txt` 每行一个 token，行号即 id；第 0 行 `<pad>`、
  第 1 行 `<unk>`，其后按频次降序、同频按码点升序
- **上限 500**：超限脚本报错退出并列出低频字符，辅助回改语料源；`<unk>`
  仅推理期出现（语料字符按定义全在词表内）
- **max_len**：报告给出语料字符长度的 P99.9 与最大值（预期 ≤ 20），
  阶段 5 训练与阶段 6 padding 以此为准
- 推理期词表外字符（标点 / 空格 / 生僻字）的处理归阶段 6 tokenizer
  （倾向直接跳过而非映射 `<unk>`），本阶段只约定语料口径

## 规则精化与基线

- **词池精化**：语料定稿后，把高频说法并入 `nlu.c` 的 `W_*` 池（如
  `beep_off` 增补 安静 / 静音），10 条优先级与函数结构不动；语料说法与
  词池冲突时以行为规格为准复核
- **`rule_baseline.py`**：镜像 `nlu.c` 词池与优先级的轻量脚本（约 30 行，
  文件头注明「与 nlu.c 同步手工维护」），对三集语料输出混淆矩阵与准确率
  ——既是阶段 6「明显优于纯规则」的对比基线，其误判清单也反哺词池精化
- **真板抽查**：从 test.tsv 抽 30 句经串口输入，对照日志中的意图标注，
  验证规则在真实链路上的表现（当前唯一输入通道是串口）

## 已知局限

- 否定未发生动作（`别开灯`）与疑问式（`灯怎么关`）不在语料内，v1 模型与
  规则均可能误判为正向动作——阶段 8 用真实输入迭代时处理
- 模板级划分下，近义但不同模板（`帮我开灯` / `帮我打开灯`）可能分属
  train / test，测试成绩略偏乐观；不做模板「族」级划分（过度设计），
  如实记录即可

## 实施顺序

1. 本文档决策点确认 → 更新 ROADMAP 意图表（补 `stop`）
2. `tools/intents.json`：意图表 + 模板 + 槽位 + unknown 词条（工作量主体）
3. `tools/gen_corpus.py`：生成 / 划分 / 自检 / 报告
4. 跑生成，按报告调语料源至达标（字符集 ≤500、无泄漏、无空类）
5. `tools/rule_baseline.py` + `nlu.c` 词池精化 + 串口抽查
6. 收尾：`data/README.md`（增语料产物说明）/ .gitignore / README /
   CLAUDE.md 同步，提交

## 验收清单

- 一条命令生成全部产物；同种子两次运行的 TSV 逐字节一致
- 报告齐备：8 类条数均衡、长度分布、字符集 ≤500、模板泄漏自检通过
- 词表格式正确（id = 行号，首两行 `<pad>` / `<unk>`），覆盖全部语料字符
- 阶段 1 验收句（开灯 / 闪 / 关灯 / 报警 / 呼吸 / 停止…）全部落在词表内
- 规则基线报告生成；词池精化前后准确率均有记录（不看绝对值，作阶段 6
  对比用）
- 构建零告警；阶段 1~3 验收项无回归
