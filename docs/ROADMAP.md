# 项目路线图

ESP32-S3-NLU 的分阶段实施计划：在正点原子 DNESP32S3 开发板上实现"文本自然语言 → 板载工具调用"的完全本地推理系统。共 8 个阶段，每阶段结束都有可独立演示的交付物，不存在半成品。

## 项目定义

- **功能**：通过串口 / WiFi 输入自然语言文本（如"请帮我点灯"），板载 NLU 模型理解意图，调用片上工具（LED、蜂鸣器、屏幕）
- **推理方式**：完全本地（ESP32-S3 端侧小模型），无云端依赖
- **输入通道**：串口、WiFi 为模型输入端；按键为屏幕控制通道（清屏 / 滚动，不经模型）
- **输出**：LED 状态、蜂鸣器节奏、2.4 寸 LCD 显示、串口 / WiFi 文本回发

## 系统架构

四层解耦结构，理解层与执行层互不感知——理解层从规则匹配升级为端侧模型时不改动执行层；执行层新增工具时不影响理解层。

```text
输入层                    理解层         响应层            执行层
─────────────────────────────────────────────────────────────────────
串口任务 ─┐
          ├─→ cmd_queue ─→ NLU ──→ 回复模板组合 ──→ 工具注册表 ──→ LED
WiFi 任务 ─┘              （规则/模型）  （前缀×主体×后缀）  │        ├─ 蜂鸣器
                                                          │        └─ LCD / 回发
按键任务 ──→ ui_queue（清屏 / 滚动）────────────→ LCD
```

| 层 | 职责 | 可替换性 |
| --- | --- | --- |
| 输入层 | 串口 / WiFi → 命令队列；按键 → 屏幕命令 | 可扩展（未来可加语音） |
| 理解层 | 文本 → 意图（含 unknown 拒识） | 阶段 6 由规则切换为模型 |
| 响应层 | 意图 + 实时状态 → 组合式回复文本 | 独立可调 |
| 执行层 | 工具注册表：意图 → 硬件动作；维护设备状态 | 工具可扩展 |

## 阶段 1：工程骨架与执行层

**做什么**

- 搭建四层工程结构：输入层 / 理解层 / 响应层 / 执行层，FreeRTOS 任务 + 命令队列串起来
- 执行层：LED 驱动（常亮 / 常灭 / 5Hz 闪烁）、蜂鸣器驱动（0.5Hz / 2Hz / 停止）、工具注册表
- 输入层：串口任务（读一行）、按键任务（轮询 XL9555，直接调工具，调试通道）
- 理解层先用关键词规则占位（阶段 6 被模型替换，规则永久保留为兜底）

**学到**：分层架构、FreeRTOS 队列 / 定时器、正点原子 BSP 移植（XL9555、GPIO）

**完成标志**：串口敲"开灯"→ LED 亮；按 KEY0 → 蜂鸣器报警；节奏任务可被"停止"打断

## 阶段 2：响应层 2.0

**做什么**

- 模板组合引擎：`前缀池 × 主体模板 × 后缀池`，从执行层读实时状态填充（如"灯现在是闪烁模式"）
- 执行层维护状态结构（led_state / beep_state），供响应层查询

**学到**：状态机设计、伪生成式文本组装

**完成标志**：同一意图多次执行，回复措辞随机变化且状态描述准确

## 阶段 3：屏幕接入

**做什么**

- 移植正点原子 10_spilcd 的 BSP（2.4 寸 SPI LCD）
- 字库方案：字库文件放 flash 分区，按码点取模渲染中文
- UI 两区布局：状态区（LED / 蜂鸣器当前模式）+ 对话区（最近几条交互）

**学到**：SPI 驱动、字库与取模、图形渲染基础

**完成标志**：串口敲命令 → 屏幕同步显示对话与状态变化

## 阶段 4：数据工程

**做什么**

- 意图表定稿（7 个意图 + unknown，见下表）
- Python 生成脚本：模板 × 同义词组合，每意图数百条 + unknown 语料（含"今天天气不错"这类无关句）
- 词表导出（字符集）、数据划分 train / val / test

**意图表**

| 意图 | 触发说法示例 | 执行 | 回复示例 |
| --- | --- | --- | --- |
| led_on | 开灯 / 请帮我点灯 / LED亮 | LED 常亮 | 灯已点亮 |
| led_off | 关灯 / 熄灭 | LED 常灭（并停止闪烁） | 灯已关闭 |
| led_blink | 让灯闪 / 闪烁模式 | LED 5Hz 闪烁 | 灯开始闪烁 |
| beep_breath | 呼吸声 / 慢速提示 | 蜂鸣器 0.5Hz | 已开启呼吸提示音 |
| beep_alarm | 报警 / 快响 | 蜂鸣器 2Hz | 已开启报警提示音 |
| beep_off | 关闭蜂鸣器 / 安静 | 蜂鸣器停止 | 蜂鸣器已关闭 |
| stop | 停止 / 全停 / 都停下 | 灯与蜂鸣器全部停止 | 已全部停止 |
| unknown | （无关输入） | — | 抱歉，我没听懂 |

**学到**：数据集设计、中文语料特点、数据增强

**完成标志**：语料集统计报告（各意图条数均衡）+ 词表覆盖检查通过

## 阶段 5：模型训练与量化

**做什么**

- 字符级 TextCNN 训练（Keras）：`Embedding(≈500字, 32维) → 并联 Conv1D(k=2,3,4 × 64) → GlobalMaxPool → Dense(softmax)`
- 评估：测试集准确率（目标 ≥95%）、混淆矩阵、unknown 拒识率
- int8 全整型量化 + 量化前后精度对比，导出 C 数组

**学到**：文本分类模型、量化原理与实操、模型评估方法

**完成标志**：<100 KB 的 int8 模型 + 一份精度评估报告

## 阶段 6：端侧集成

**做什么**

- 接入 `esp-tflite-micro`，C 侧 tokenizer（UTF-8 切字 → 词表 → padding）
- 推理任务替换规则匹配；置信度阈值：低于阈值 → 规则再试一次 → 都不中 → unknown 回复
- 阈值调优（用阶段 4 测试集 + 手敲真实输入验证）

**学到**：TFLM 部署、端侧推理优化、置信度与拒识策略

**完成标志**：串口手敲 20 句现编口语（不照抄训练语料）通过率 ≥2/3，明显优于纯规则

## 阶段 7：WiFi 通道

**做什么**

- WiFi 连接（STA 连路由 / AP 自建热点，例程 13~15 可参考）
- HTTP Server + 内嵌网页：手机浏览器输入文本 → 投命令队列 → 结果显示在网页
- 与串口共用同一条队列（顺序执行，互不打架）

**学到**：ESP-IDF 网络栈、HTTP Server、嵌入式网页

**完成标志**：手机浏览器输入"请帮我点灯"→ 灯亮 + 网页显示回复

## 阶段 8：迭代打磨

- 收集真实输入（串口 / WiFi 日志）→ 补进语料 → 重训循环
- 回复语池扩充、UI 打磨
- 可选扩展：更多工具 / 意图、状态查询意图（"现在灯什么状态"）、语音输入（架构支持换输入源）
